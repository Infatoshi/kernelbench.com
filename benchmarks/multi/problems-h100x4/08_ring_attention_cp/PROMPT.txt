I need you to write a fast context-parallel causal attention for a 4xH100 SXM node (NVLink4, ~900 GB/s/GPU bidirectional, fully connected via NVSwitch). This runs across all 4 GPUs under torchrun. The reference is in reference.py and your kernel goes in solution.py. Make whatever mess you want in this directory — scratch kernels, build artifacts, nsys traces — but the final answer must be in solution.py with the same Model, get_inputs, and get_init_inputs interface as reference.py, and it must work when launched on world_size=4.

The setup: one long sequence is split contiguously across the 4 GPUs. Rank r owns sequence positions [r*seq_local, (r+1)*seq_local) and holds only its own q, k and v, each shaped (seq_local, heads, head_dim) in bf16. Each rank must return the causal attention output for its own queries, shaped (seq_local, heads, head_dim) in bf16. Causal means global position: my query at local index i sits at global position r*seq_local + i and attends to every key at global position <= that, which for every rank except rank 0 means most of the keys live on other GPUs. Softmax scaling is the usual 1/sqrt(head_dim). Read reference.py — it defines exactly this, by gathering all the K/V and running one masked fp32 SDPA. That is the oracle, not a template: gathering the whole context is what you are trying to beat.

The standard approach is a ring. Pass K/V chunks hop by hop around the fabric and accumulate partial attention with an online softmax rescale (running max and running denominator, flash-attention style), so you never materialize the full context and you can be transferring the next chunk while computing on the current one. Getting that overlap right is most of the work.

The other half of the problem is load balance, and it is worth thinking about before you write code. With contiguous sharding under a causal mask, rank 0's queries attend to one chunk and rank 3's attend to four, so the useful work is 1:2:3:4 across ranks. The harness times the SLOWEST rank, and the ring runs in lockstep, so a naive implementation leaves rank 0 idle three quarters of the time and you get graded on rank 3. Whether you fix that by moving queries, splitting the causal triangle, reordering which positions a rank processes, or something else is your call — the only contract is that each rank returns the correct output for the positions it owns, in local order.

Local attention math may use any library you like — torch SDPA, flash-attn, cuDNN, or your own kernel. The chunk exchange may NOT: do not use torch.distributed.all_gather, dist.all_gather, any other c10d collective, or the functional collectives. Move the K/V yourself with fine-grained NVLink primitives — CUDA symmetric memory (torch symmetric memory / multimem), NVSHMEM, or p2p copies you schedule on your own streams. Investigate the headers and docs yourself.

You are graded on geomean speedup against a frozen baseline: NCCL all-gather of K/V followed by one masked bf16 SDPA over the full context. Correctness tolerance on the bf16 output is 2.5e-2 rel (abs term scaled to the output rms), checked across every shape, 5 rank-distinct trials, and numeric-stress rescales — an online-softmax accumulation has to be numerically sound, not just approximately right. The shapes you must handle: seq_local=2048 heads=32 head_dim=128 (8k total context), seq_local=4096 heads=16 head_dim=128 (16k context, fewer heads so there is less math per hop to hide the transfer behind), seq_local=512 heads=32 head_dim=128 (2k context, latency-bound — ring startup dominates), and seq_local=2000 heads=32 head_dim=128 (off-alignment sequence length, not a multiple of any convenient tile).

Your flywheel: implement, profile (nsys to confirm transfers actually overlap the attention kernels and to see the per-rank idle time, ncu for the attention itself), time it with benchmark.py, verify with `python check.py`, then iterate. Don't substitute your own correctness snippet for check.py — it runs all shapes across all ranks with distinct inputs; your spot check won't. If check.py hasn't printed PASS, you're not done. Take as long as you need to actually push the number up.
